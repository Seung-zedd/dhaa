## 핵심 결론 — 세 프로젝트는 경쟁 관계가 아니다

셋 다 스스로를 "에이전트 OS"라고 부르지만, 실제로 건드리는 지점이 서로 다릅니다.

```
┌─────────────────────────────────────────────┐
│  프로세스 / 거버넌스   →  MoAI-ADK          │  어떻게 일할 것인가
│  (SPEC, TRUST 5, 추적성)                    │
├─────────────────────────────────────────────┤
│  콘텐츠 / 카탈로그     →  ECC               │  무엇을 쓸 수 있는가
│  (에이전트, 스킬, 커맨드)                    │
├─────────────────────────────────────────────┤
│  런타임 / 하네스       →  OmO               │  도구가 어떻게 동작하는가
│  (편집 툴, LSP, 모델 라우팅, MCP 수명)       │
└─────────────────────────────────────────────┘
```

따라서 "어느 것으로 갈아탈까"가 아니라 **"우리 레이어에 없는 아이디어를 어디서 가져올까"** 가 올바른 질문입니다.

## 조사 방법과 한계

- 세 문서 모두 **저장소 공개 파일 직접 열람** 기준입니다. 각 문서 상단에 실제 읽은 파일 목록을 명시했습니다.
- ECC·OmO의 성능 수치는 **전부 메인테이너 자체 보고값**이며 외부 벤치마크가 아닙니다. 인용 시 출처를 함께 밝혔습니다.
- 실행 검증(설치·구동)은 하지 않았습니다. 문서와 코드 구조 기반 분석입니다.
